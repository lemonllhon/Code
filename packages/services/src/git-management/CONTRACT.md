# Git management

Private `git/account` inspect/bind bridges an authorized remembered account preference to the existing routing CAS owner. It exposes only matching metadata, never credentials, and reuses session/workspace/cwd authorization. HTTP targets differing only by one consistent username hint share their binding; conflicting explicit hints remain separate and conflicting legacy bindings stop. The Agent `Git` tool executes each network command as argv through the original execution/checkout/recovery port, retaining its actual result. No Shell rewriting or automatic write replay is introduced.

The private Agent Git context is a read-only projection of the same repository routing owner. It exposes effective account metadata and match status for authorized source directories without resolving secrets, refreshing OAuth or granting writes. Runtime context is transient; durable Git workflow lessons stay in the original Project Memory writer. See `specs/git-project-memory-integration.md`.

The context-only read refreshes repository URLs, saved profile and legacy selection on every call. When all targets have explicit selections (including stale/conflicting selections), or there are no remotes, it skips external candidate discovery. Automatic matching, the account menu and execution credential resolution retain full discovery and authentication. This is not a cached authorization decision.

Repository authentication is resolved by one Host routing adapter for managed UI Git and private Agent `git/credential` requests. Public repository queries and CAS binding commands contain no secrets. Bindings isolate normalized workspace identity, canonical Git common-dir and actual remote URL; linked worktrees reuse the repository choice and detected accounts can be selected directly. Explicit automatic selection suppresses legacy clone IDs. The private stdio response is consumed only by a process-scoped Git/SSH helper from the provider-node public entrypoint, never by model/session events or Renderer. Details and validation cases: `specs/git-account-routing.md`.

Single Host owner for encrypted Git configuration and credentials. Public `IGitManagementService` returns secret-free snapshots and accepts revision-checked mutations. `CredentialService` owns encryption; the adapter takes a cross-process lock across read/update/save. Command authentication is a Host-only port, never exposed through RPC. UI owns only unsaved form drafts. Remote workspaces use their own Host service.

Repository effects retain checkout coordination, acquisition preview, network journal, request IDs and recovery reservations. No account mutation triggers Git repository writes. No plaintext credentials in URLs, argv, ordinary settings, results or logs.

Detection is read-only and Host-scoped: CLI/static credential files enumerate multiple accounts; bounded, noninteractive GCM `github list` enumerates system-managed GitHub accounts without extracting tokens. Imported system accounts constrain Git credential lookup by username, preserving other tools' active accounts. SSH details read only the matching `.pub`, validate its SSH wire format and compute SHA256 over the public blob; private key bytes are never read. Public detection adds optional-compatible `sshKeys` metadata, never secret material. Each source fails independently with fixed diagnostic categories. UI detects on entry and displays candidates by provider; import remains an explicit CAS mutation.

System discovery uses injected, bounded metadata-only adapters for WinCred, macOS Keychain attributes and Linux Secret Service attributes. No secret extraction, unlock, login or arbitrary shell is admitted by discovery. Provider evidence comes from explicit CLI/saved-account/Git provider mappings before hostname inference. Accounts deduplicate by canonical server/path and username without dropping distinct users. Old candidates are invalidated when their source/authentication changes. The additive `systemCredentialSources` result exposes only source/status/count, making unavailable sources distinguishable from empty results. Details and acceptance cases live in `specs/git-management-and-authentication.md`.

Explicit `authorize` commands are separate from read-only discovery. One Host authorization owner holds idempotent request IDs, PKCE/device state and pending grants, enforces cancellation/expiry, and returns no tokens. Public OAuth clients are user-configured by Client ID. `mutate(type=authorize)` verifies the pending grant under the existing profile CAS lock; browser identity and server come only from the verified grant. Access/refresh tokens remain encrypted in the profile. Refresh is serialized under the same lock and preserves the public account revision when identity is unchanged. The native callback listens only on loopback; remote browsers may submit the final callback URL to the same owner. No Main/relay business state or Git write/recovery path is introduced.

The Git owner owns one OAuth-scoped network transport through the existing provider network public entrypoint. It opts into OS trust on Windows/macOS/Linux, retains default/extra/custom CA and current Host proxy policy, keeps TLS hostname/chain verification, and disposes connections with the owner. Token exchange and refresh share that port. Public failures expose fixed diagnostic codes only; OAuth bodies, authorization codes and raw network exceptions remain private.
